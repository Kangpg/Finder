Finder 개발 경과와
이슈 추적 및 Everything 비교

대상은 Finder 0.1.0 Windows x64입니다. 10월 14일부터 29일까지의 개발 기록과 현재 소스, 사용자가 보고한 증상, 공식 Everything 문서를 종합했습니다. 날짜는 검증 기록 기준이며 이슈 ID는 이번 보고서에서 부여했습니다.

현재 결론

파일명 검색 도구에서 출발해 백그라운드 갱신과 검색, 분할 창, Windows 파일 작업, 상주 실행, 설치 배포까지 구현했습니다. 제품 방향은 개발 작업 폴더를 빠르게 찾고 바로 조작할 수 있는 로컬 도구입니다.

가장 중요한 미종결 항목은 포커스 시 시스템 전체 지연과 실제 NTFS 변경 추적 검증입니다. 검색 가속이나 DX12 장치 검사만으로 두 항목이 해결됐다고 처리하지 않습니다.

이전 대화의 “Everything은 32비트만 지원한다”는 전제는 정정합니다. 공식 Everything도 x64를 제공하므로 Finder의 차별점은 비트 수 자체가 아니라 맞춤 작업 흐름과 구현 선택에 있습니다. [W1, W2]

유지할 설계 원칙

작업 소유권을 분명히 합니다. UI는 표시와 입력, 검색은 불변 색인, 행 작업자는 속성의 최신 여부, Windows Shell은 아이콘과 네이티브 동작을 담당합니다.

빠른 경로와 정확한 대체 경로를 함께 둡니다. 역색인을 쓸 수 없는 조건은 전체 검사로 돌아갑니다. 가속 자료의 존재가 검색 결과의 의미를 바꾸지 않습니다.

사용자의 작업 상태를 유지합니다. 갱신 중 기존 결과를 유지하고 선택을 복원하며, 설정을 백업하고 사용자 데이터와 실행 중 프로세스를 배포 작업에서 보존합니다.

시스템 구성

02 / ARCHITECTURE

색인 게시와 스냅샷 참조에는 짧은 Mutex 구간이 있습니다. 검색이 기존 Arc를 유지하는 구조이며 lock-free를 뜻하지 않습니다. 기본 검색 풀 4스레드와 색인 풀 2스레드는 각각 정해진 CPU 예산입니다. [L1, L2]

posting은 gram을 포함할 수 있는 파일 ID 목록입니다. 가장 작은 필수 목록을 골라 후보를 줄이고 원래 AST로 검증합니다. 해시 충돌·delta·삭제를 반영하며 GUI는 전체 일치 수와 상위 5,000개를 구분합니다. [L1, L2]

동봉한 JSON은 ID·우선도·상태·원인·조치·검증·후속 조건을 담고, CSV는 스프레드시트에서 정렬할 수 있습니다. 같은 증상은 기존 ID에 근거를 추가하고 종료 기준을 충족한 뒤 상태를 바꿉니다. 외부 이슈 시스템에는 등록하지 않았습니다.
